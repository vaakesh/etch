Etch готов расти, но выпускать текущую сборку рано

Проект уже выглядит как цельный продукт для словарных карточек: есть библиотека, каталог, практика, история и профиль. Главный риск сейчас находится в целостности данных и границах пользовательских сессий. До развития новых функций стоит закрыть три критических дефекта и стабилизировать контракт между backend, frontend и БД.

Critical F01. Кэш frontend может показать данные предыдущего аккаунтаКонфиденциальность · session boundary

Главная, карточки библиотеки, практика и история хранят данные в module-level переменных. Они не имеют ключа пользователя и не очищаются при logout/login. AuthProvider остаётся смонтированным, поэтому после смены аккаунта в той же вкладке новый пользователь может сначала увидеть данные прежнего.

Исправление: сделать единый session-scoped cache с ключом user.uuid + sessionRevision; очищать все персональные кэши при signed-out, signed-in и финальном 401.

Места
useHomeDashboard.ts:23, useLibraryCards.ts:50, usePracticeHistory.ts:43, usePracticeSessionHistory.ts:38
Риск
Межаккаунтный показ колод, карточек и истории обучения.
Критерий
E2E: A → logout → B; ни один экран не содержит данные A.
Critical F02. Удаление приватной колоды создаёт публичную копиюКонфиденциальность · жизненный цикл данных

delete_deck() всегда вызывает архивирование, а _copy_deck() всегда задаёт is_public=True. Воспроизведение показало: приватная колода превращается в публичную копию владельца с жёстко заданным ID 1. Это противоречит обещанию интерфейса «действие нельзя отменить» и настройке приватности.

Исправление: не архивировать приватные колоды; публичную копию создавать только при наличии реальных сторонних сохранений, сохранять исходную видимость и использовать системного владельца по UUID/конфигурации.

Места
decks/service.py:52, 131, 550, 662
Воспроизведение
private → delete → archive is_public=true
Критерий
Удалённая приватная колода недоступна ни по UUID, ни в каталоге.
Critical F03. Нельзя удалить карточку, связанную с колодойPostgreSQL · основной сценарий

Перед удалением строится SELECT DISTINCT ... FOR UPDATE OF decks. PostgreSQL отклоняет такой запрос: FOR UPDATE is not allowed with DISTINCT clause. Ошибка подтверждена через EXPLAIN на локальной БД. Операция удаления ломается именно для карточек в колодах.

Исправление: сначала получить уникальные ID без блокировки, затем отдельным запросом заблокировать строки Deck; покрыть реальным integration-тестом.

Место

Критерий

Исправление: инвалидировать сущность колоды при любом изменении видимости, UUID lookup, страницы каталога и зависимые preview/card caches.

High F05. Сбой Redis превращается в AttributeError и может остановить APIНадёжность · rate limiting

RedisRateLimiter.check() перехватывает RedisError, затем вызывает self._log_redis_error(). Этот метод существует только у другого класса — RedisCacheService. Воспроизведение со simulated outage дало AttributeError. Поскольку limiter подключён к большинству routes, Redis становится единой точкой отказа.

Исправление: использовать module logger, явно выбрать fail-open/fail-closed policy по типу route и добавить тест отключённого Redis.

High F06. Пагинация библиотеки падает на неизученных колодахBackend · cursor contract

UserDeck.last_studied_at корректно допускает null, но LibraryCursor.last_studied_at требует datetime, а serializer вызывает .isoformat(). Если граница страницы приходится на ещё не изученную колоду, создание next cursor завершается validation error и API отдаёт 500.

Исправление: разрешить null в cursor schema и serializer/deserializer, закрепить порядок NULLS LAST тестами на переход через обе группы.

High F07. Кнопка «Сохранить» в профиле ничего не сохраняетЛожное успешное действие · UX

High F08. Модели и последняя миграция расходятсяСхема данных · deployment

Главная ставка: ежедневное удержание знаний

Сейчас практика выбирает случайные карточки и проверяет точное совпадение ответа. Это хорошая демонстрация, но слабая причина возвращаться каждый день. Наиболее сильный путь — превратить Etch в персональный план повторений, где пользователь всегда знает, что учить сегодня и почему.

«Открыть Etch и за 10 минут закрыть все карточки, которые пора повторить сегодня».

Основной цикл

1
Добавить
Импорт, каталог, собственная карточка.
2
Выучить
Короткая первая сессия с подсказками.
3
Оценить
Again / Hard / Good / Easy.
4
Повторить
Персональная очередь на сегодня.
5
Увидеть эффект
Retention, streak, прогноз нагрузки.
Рекомендуемый алгоритм. После исправления данных стоит оценить FSRS: он моделирует запоминаемость и планирует интервалы по истории оценок. Начать можно с совместимого сервера и простого UI из четырёх оценок, не показывая пользователю математику. Референс: Open Spaced Repetition / FSRS.
