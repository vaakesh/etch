# Инвалидация кэша

- Использовать только `CacheInvalidator.invalidate()` и `scopes` из `app.redis.invalidation`.
- Создавать `UserDeckIdentity` через `make_user_deck_identity()`.
- Сначала искать подходящий метод в `scopes`; если его нет — добавить.
- Если задачу нельзя решить через `scopes` — сообщить пользователю и не менять код.
- Проверять изменяемые поля, связи, каскадные удаления, переносы и данные, встроенные в кэш других сущностей.
- Перед выбором скоупов проследить запись и чтение кэша до SQL: что хранится, кто попадает в выборку, какие поля задают фильтры и порядок. Не судить по названиям и памяти.
- Пользователей для страниц выбирать по условиям этой страницы; наличие `UserDeck` или истории обучения не означает `is_saved=True`. Учитывать все варианты страницы с общей generation.
- Учитывать всех затронутых пользователей, включая владельцев, получателей и сохранивших чужие колоды.
- Собирать ID, UUID и ключи связей до удаления или переноса; сохранить их до commit.
- Вызывать инвалидацию в сервисе после успешного commit, одним вызовом со всеми нужными скоупами.
- Redis — обязательная зависимость: `invalidate()` пробрасывает `RedisError` (ответ 503). Не перехватывать её в сервисах.
- Для outbox: `dump_scopes(scopes.method(*args), ...)` → JSON-совместимый dict → payload события `cache.invalidation.v1`; сохранять в транзакции с изменениями. Обработчик: `invalidate(*load_scopes(payload))`. `load_scopes()` возвращает список `Scope`, который нужно раскрывать через `*`.
- Аргументы-сущности в outbox передавать как `EntityIdentity(id, uuid)`. Повторная доставка допустима, generation может увеличиться повторно.
- Сбрасывать только устаревающие данные. Создание сущности само по себе не требует сброса её кэша, но может менять списки.
- Инвалидировать страницы при изменении состава, фильтрации или порядка. Изменение данных сущности не требует сброса страницы, хранящей только ID.
- Изменение только `saves_count` не требует сброса кэша колоды: счётчик обновится по TTL.
- При удалении сбрасывать кэш сущности, UUID→ID, удалённые связи и затронутые страницы.
- Проверять тестами нужные скоупы и отсутствие инвалидации при ошибке транзакции.
